# Project Setup Guide

How to set up a **new** project to run under the Lifecycle Framework with the agent team. Do Part 1 once per machine and Part 2 once per project. Finish with the Part 3 acceptance checks before the first `#T-PhaseEntry`.

For running the project once it's set up, see the **Developer Runbook**. Every path and name used here is defined in **`Naming-and-Paths`**.

All paths use `/`.

---

## Part 1 — Machine Setup (once per machine)

1. **Claude Code Desktop** installed and signed in.
2. **Git** installed and on PATH.
3. **Python:** check `py --version`, then `py -m pip install openpyxl` (the tracker tool's dependency).
4. **Toolchains** for your stack (e.g. Go, Rust, Node, `tygo`), each on PATH. **Restart Desktop after installing any toolchain**: it reads PATH only at launch.
5. **Playwright browsers**, if any project uses Playwright for e2e: `npx playwright install`.
6. **Projects base folder:** keep every project under one base folder, e.g. `C:/Users/{you}/OneDrive/Documents/Code`.
7. **User settings** (`~/.claude/settings.json`, i.e. `C:/Users/{you}/.claude/settings.json`): merge in `user-settings-template.json` from the framework home, replacing:
   - `{BASE}` = the base folder with `/`, e.g. `C:/Users/{you}/OneDrive/Documents/Code`;
   - `{BASE_RULE}` = the same path in rule form, e.g. `//c/Users/{you}/OneDrive/Documents/Code`.

   This grants Claude Code sessions access to every project's `Documentation/`, once for all projects, so no project needs its own path settings.
8. **Desktop settings:**
   - "Auto-archive after PR merge or close": **off**;
   - agent teams: **off** (not available in Desktop anyway).

## Part 2 — Project Setup (once per project)

### 2.1 Project Folder and Structure

1. **Create the project folder** under the base folder, named **exactly the project name, with no spaces** (e.g. `ShadowChain`). The folder name *is* `#PN`; it is not written anywhere else.
2. **Copy the Project Template** (`Shared Documents/Project Template/Project/`) into it. This gives the full folder structure:

```
{PN}/
├── Naming-and-Paths.md                            #NP: every ID, path and folder rule (unversioned; version in header)
├── Documentation/                                 #DP
│   ├── {PN}-Register.xlsx                         live, unversioned: About · Requirements · Open Decisions · Backlog
│   ├── Project-Tracker-{PN}.xlsx                  live, unversioned: About · Summary · PH-{PH} · WS-{WS}
│   ├── Roadmap-{PN}.md                            live, unversioned; framework version in header
│   ├── {PN}-Design-Specification-vX.X.docx
│   ├── Archive/
│   ├── Design_Spec_Dense/                         generated by T-DD; never edited by hand
│   ├── Protocol/                                  top level: triggerable T-*.md only
│   │   ├── Archive/
│   │   ├── Support/                               read by protocols, never triggered (+ Archive/)
│   │   └── Learning/                              live, AI-maintained planning records
│   ├── Governance/                                read-only framework copies
│   │   ├── Process/      Setup/      Execution/   (each + Archive/)
│   │   └── Templates/                             (+ Archive/)
│   └── Implementation/                            live and completed records
│       ├── Checklists/   (+ Completed/)
│       ├── Summaries/
│       ├── Plans/        (+ Archive/, Completed/)
│       ├── DevTests/     (+ Archive/, Completed/)
│       └── Records/      Ledgers/ · Handovers/ · Reviews/   (each + Completed/)
└── Code/                                          #CP: git repository
    ├── CLAUDE.md
    ├── .claude/      agents/ · hooks/ · skills/ · settings.json · execution-config.md
    └── tools/
```

`PH-{PH}/` folders inside `Implementation/` are created at runtime, when each phase closes.

### 2.2 Documentation Baseline (`#DP`)

1. **Project Register** `{PN}-Register.xlsx`, with four tabs:

   | Tab | Columns |
   | --- | --- |
   | About | `Register schema`, `Framework version`, `Updated` |
   | Requirements | your requirement columns, plus `Status` (incl. `Proposed`) |
   | Open Decisions | `ID` (`OD-nn`), decision, status, notes |
   | Backlog | `ID`, `Type`, `Description`, `Linked Req / OD`, `Origin`, `Status`, `Target WS`, `Notes` |

   - Backlog `Type`: Deferred Scope, Tech Debt, Edge Case, Design Drift, Parked.
   - Backlog `Status`: `Open`, `Planned`, `Done`, `Rejected`, `Pending #T-DU`, `Parked`.
2. **Project Tracker** `Project-Tracker-{PN}.xlsx` (unversioned: it changes constantly), with two tabs: `About` (`Tracker schema`, `Framework version`, `Created`) and `Summary` (columns `ID`, `Title`, `Status`, `Completed`, `Notes`). Statuses: `Not Started`, `In Work`, `Complete`, `Parked`. `PH-{PH}` and `WS-{WS}` tabs are created later by the gate protocols. No charts or images: the tracker script would drop them.
3. **Roadmap** `Roadmap-{PN}.md` (unversioned: every gate updates it), with the framework version in its header and the phase outline. Work stream specs are added by `#T-PhaseEntry`.
4. **Design source** `{PN}-Design-Specification-vX.X.docx`, at the Documentation root.
5. **Framework files** are already in place from the template copy (2.1). Set the Register's `About → Framework version` to `5.0`. Framework copies are never edited locally; updates enter only at `#T-PhaseEntry`.

The design Profile (`Protocol/Support/Profile-{PN}-DD`) is **not** created by hand; `#T-DP` drafts it in 2.6.

### 2.3 Code Repository (`#CP`)

1. Initialise the repo:

   ```
   git init
   git checkout -b develop
   ```

   Add `origin` now if the project will push to a remote.
2. **Framework files** are already in place from the template copy: `.claude/` (agents, hooks, skills, `settings.json`), `tools/`, `.gitattributes`, `.worktreeinclude` and `.gitignore`. `settings.json` is generic and `.gitignore` is complete: no edits needed.
3. **`CLAUDE.md`** is already in place at `Code/CLAUDE.md` from the template copy. It contains nothing project-specific.
4. **`.claude/execution-config.md`:** create it from the Execution Config template. Set:
   - `#GR` (`develop`), `#REMOTE` and `#MAX_PARALLEL` (default 2);
   - the tracker column names;
   - the Worktree Setup, test and Health Check commands for your stack.
5. **`.claude/skills/project-rules/SKILL.md`:** add any project-specific excluded directories (build output and generated folders only, never source). Mirror any additions as `Read(...)` deny rules in `settings.json`.
6. **`.claude/skills/codebase-lessons/SKILL.md`:** leave as the empty template; the Team Lead fills it.
7. **Commit** everything on `develop`:

   ```
   git add -A
   git commit -m "Project setup"
   ```

   Push if `#REMOTE`.

### 2.4 CoWork Project

Create the CoWork project, connect the **`{PN}` project folder** (the root, not `Documentation/`), and paste `CoWork-Project-Instructions-Template` into its instructions **as-is**. It contains nothing project-specific.

### 2.5 Optional, Per Project

- **Code intelligence plugins:** for each language, decide whether to add a language-server plugin (e.g. `typescript-lsp`, a rust-analyzer plugin). If adopted:
  - install the language server binary first, then the plugin (Desktop: **+ → Plugins**), then confirm the server starts;
  - add the code-intelligence tool to the `tools:` list in `pkg-developer` and `pkg-integrator`.
- **Stack conventions skill:** only if agents repeat the same language or style mistakes. Add a `stack-conventions` skill and preload it into the package agents.

### 2.6 Design Profile and Densification

1. **Draft the Profile:** `#T-DP source={PN}-Design-Specification-v0.1.docx` (the project name defaults to the folder name). It writes `Protocol/Support/Profile-{PN}-DD-v1.0-DRAFT.md` and stops.
2. **Review the draft:** resolve every `TODO` key, check `omit_sections` and the `shard_seed`, then remove `-DRAFT` from the filename.
3. **Densify:** `#T-DD` (in Claude Code or CoWork). Approve the shard map at its Pass 1 Gate. It generates `Design_Spec_Dense/`, which phase and work stream planning depend on.

## Part 3 — Acceptance Checks (once per project, before the first Phase Entry)

| Check | How | Pass |
| --- | --- | --- |
| Naming-and-Paths first (Claude Code) | Fresh session started in `#CP`; ask: "what are `#PN`, `#DP` and `#CP`?" | Reads `{Root}/Naming-and-Paths.md` before any other file; correct answers |
| Naming-and-Paths first (worktree) | Same, in a session with the worktree option ticked | Same file found, same answers |
| Naming-and-Paths first (CoWork) | Same question in a fresh CoWork session | Reads `Naming-and-Paths.md`, then `project-rules`; correct answers |
| CLAUDE.md and import | Ask: "quote the first excluded directory from project rules" | Answers from `project-rules` |
| Documentation reachable | Read any file under `#DP/Protocol/` | Reads without a permission prompt |
| Deny rules | Try to read a file under `#DP/Design_Spec_Dense/_work/` | Denied |
| CoWork project rules | Fresh CoWork session: ask it to list `Archive/` | Refuses (banned) |
| `Runs in:` guard | In CoWork: `#T-TLO start ws 0.0` | Stops and redirects to Claude Code |
| Tracker script | `py tools/trkr_update.py --tracker "{#TRKR}" --sheet Summary --id PH-0 --status "Not Started" --create --dry-run` | Prints a `DRYRUN` line |
| Worktree smoke test | `git worktree add ../wt-test develop`, then run the Worktree Setup and build commands there, then `git worktree remove ../wt-test` | Builds; add any "missing file" findings to `.worktreeinclude` |

When all checks pass, start the project with `#T-PhaseEntry for ph 1` in CoWork (see the Developer Runbook).
